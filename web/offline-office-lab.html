会议行动项：先核对，再审阅，永不外发

把固定的6条合成会议事实，转成可检查的行动项草稿。先观察3个错误，再手动修订；最后由人审阅输入与提交的双SHA。这里没有模型调用，也没有真实批准记录。

动手之前

dispatch_allowed 始终为 false。不发消息、不创建日历、不分派任务。页面只提供静态材料，不运行代码、不上传输入、不请求账号。

需要已有 Python 3.10+；仅标准库，无 pip、API key、模型或真实个人数据。本次实际测试仅 Linux / Python 3.12；Windows、macOS及其他版本未验证。缺少 POSIX O_NOFOLLOW / O_NONBLOCK 时退出2，不降级。

1. 下载，先核对来源

下载原创源码 ZIP（不自动执行）

  • 完整中文教程（原文 Markdown） · 阅读规则源码 lab.py · 阅读可复现打包源码
  • ZIP及13个成员的SHA256 · 接入封存清单
  • 独立离线QA报告 · QA说明与历史问题

固定 r1 ZIP SHA256：

9f20ed0318765e8e02938f334e71b83cfe3a626afc3c675410c9e2777f575484

用本地SHA256工具核对后，解压到自己控制的新目录。哈希只绑定文件字节，不是身份认证或签名。以下命令均在解包后的 meeting-action-lab 目录运行；不自动安装软件。

2. 读事实，填写自己的答案

先读 六事实卡：F1是建议，不能写成决定；F2是协助意愿，不能虚构负责人；F5才是明确决定；F6必须保留F3和F4依赖。所有人物与会议均虚构。

复制 fixtures/submission-template.json 到新的 my-submission.json，手工填写 I1–I6，对应 F1–F6。引用须逐字一致，未知负责人/日期填 JSON null。这是固定字段规则练习，不是任意自然语言抽取。

3. 观察错误，再修订

python3 -B lab.py validate --input fixtures/meeting.json --submission fixtures/submission-bad.json
python3 -B lab.py validate --input fixtures/meeting.json --submission fixtures/submission-good.json
python3 -B lab.py validate --input fixtures/meeting.json --submission my-submission.json

bad退出1，恰好出现 KIND_MISMATCH、UNCONFIRMED_OWNER、DEPENDENCY_MISMATCH 三错；good退出0、status=pass、errors=[]。good是作者对照答案，不是模型生成结果。据错误代码修改自己的答案，直到内容验收通过。

4. 人工审阅双SHA，不默认批准

复制空的 fixtures/review-template.json 到新的 my-review.json。由人实际阅读清单后，填写报告中的 input_sha256 和 submission_sha256，明确选择 approve 或 reject；拒绝时必须填写原因。模板不预填批准，程序不生成、代替人工批准。

python3 -B lab.py review --input fixtures/meeting.json --submission my-submission.json --review my-review.json

输入或提交的任何字节（包括空白）变化，都让旧审阅失效，必须重新阅读并明确决定。即使本地练习选择approve，也仅形成合成已审阅草稿，仍不能外发。HUMAN-DEMO只是教学标签，不认证真实审阅者。包内 reviewed-draft 是单元测试预期值，不是人工批准文件。

5. 复验，再尝试重打包

python3 -B lab.py check-golden
python3 -B -m unittest discover -s tests -v
python3 -B package_lab.py --out ../my-repro-package-a
python3 -B package_lab.py --out ../my-repro-package-b

输出目录必须不存在；两次ZIP应与上面的固定SHA相同。13成员、固定时间戳/权限、排序、ZIP_STORED；不含缓存、日志或自己的审阅文件。check-golden只核对good/bad，不构造批准；19个单元测试中的approve/reject均为临时合成测试。

如何理解退出码

0：命令合法完成，不等于批准
合法reject也退出0，但 status=needs-revision、approved=false。
1：验收失败或审阅过期
按报告修订；不要绕过人工检查。
2：输入或环境不合法
参数、文件、编码、JSON/schema错误或安全文件标志缺失。缺CLI参数只打印用法，不是JSON报告。

这些结果证明什么，不证明什么

已验证的是Linux上固定六事实的原创规则模拟：19测试、25类对抗反例在源码/解包两份运行、330个schema变异无未捕获异常、可复现ZIP。不是LLM语义能力、MCP合规、办公平台效果、真实部署收益或生产授权安全证明。原132个案例数据未改，未增加模型节点，执行证据不转移给产品或MCP。

FIXED_ROWS 是教学信任根；源码及上级目录应可信。读取限制64KiB，拒绝最终分量符号链接/FIFO/设备，检查文件身份变化；这不是恶意文件系统沙箱，同步篡改源码与答案不在保证范围。不要用真实数据或连接账号；需要模型、外发或真实业务时停止并另获授权。
