把24秒的合成项目改为20秒：镜头删了，字幕是否还留着？目的时间对了，是否引用错原片？用一份自编JSON时间轴，检查分镜、字幕、音乐与图卡的版本和源区间，而不是只看总时长。

这是规则模拟，不是真实剪辑

publish_allowed=false，即使结构校验pass也不许可发布。页面只提供静态材料与下载，不执行代码、不上传输入、不请求账号。没有模型调用、SDK、真实媒体或音画播放。

需要已有Python 3.10+，仅标准库，无pip、API key或自动安装。作者实际验证环境为Linux / Python 3.12.14；Windows、macOS及其他Python版本未验证。缺少POSIX O_NOFOLLOW / O_NONBLOCK时退出2，不降级。

项目paper-demo-r1全部由原创文字占位组成，不包含视频、音乐或图像文件。删除原时间[8000,12000)，生成paper-demo-r2。以下数值均为毫秒，左闭右开，速度恒为1，不包含变速、叠化或帧率转换。

前保留窗k1=[0,8000)不移动；后保留窗k2=[12000,24000)平移−4000ms。k1/k2是保留窗编号，不是幸存片段重新编号。素材ID和源坐标不能随目的时间一起猜改。

2. 手填提交，先观察一处错误

  1. 阅读固定source与固定edit。将fixtures/submission-template.json复制到新文件my-submission.json，手工填写四轨；模板缺少片段，预期不能通过。
  2. 在解包后的creative-delivery-lab目录运行以下命令。输出到终端，不要重定向覆盖输入。
python3 -B lab.py validate --submission fixtures/submission-F07b.json
python3 -B lab.py validate --submission fixtures/submission-F08.json
python3 -B lab.py validate --submission fixtures/submission-good.json
python3 -B lab.py validate --submission my-submission.json

看primary主因，不重复计算同一个故障

  • F07b：仅把S2.k2目的起点8000改成8001，出现1ms空洞。SHOT_COVERAGE_GAP为primary；DEST_INTERVAL_MISMATCH和SOURCE_DEST_LENGTH_MISMATCH为derived，cause_id指回主因。
  • F08：将存活C3“两者并排。”改为“纸圆并排。”，出现TEXT_CHANGED。时间正确不等于内容正确。
  • F09：只有音乐交付摘要故意沿用旧版本。其他单错夹具都先做指定变异，再统一重算摘要；不要把摘要通过误当内容通过。

24项golden为作者good加23个坏例；期望按冻结契约预先定义，不是生产校验器自行生成的正确性证明。独立手算oracle给出10个保留片段；good是作者答案，不是模型生成结果。F14在临时副本联合篡改题目与提交，须被代码内题目信任根拒绝。

4. 证据与停止边界

已执行的是这一个自编lab：作者25项测试、24项golden通过；独立实现QA覆盖50次CLI检查及1394项补充检查，解包25项测试与24项golden通过，并验证可复现ZIP。这些结果不转移给既有案例、模型、MCP、音视频或设计产品，不证明部署收益或行业最佳实践。

CLI只读固定题目和显式提交的普通文件；限64KiB（65536字节），严格字段、数量、深度和类型，拒绝重复JSON键、非有限数、末段symlink、FIFO及设备文件，核对读入文件身份。上级目录应由学习者控制；不是恶意文件系统沙箱，同步篡改源码与答案不在保证范围。

这是自编JSON契约，不是WebVTT、SRT、OTIO，不声称格式兼容或可访问性合规。所有文字素材均为合成占位，synthetic_fixture只是教学来源记录，不是版权声明的法律授权证明。若需要真实媒体、账号、模型、上传、收费、法律判断或发布，停止本课范围并另行明确授权。
