# AgentWork 学习、写作与知识实践分册

> 查证日期：2026-10-28。14个原创合成案例；全部为D级：官方文档依据＋原创教学设计，未实测。本文不是对AgentWork现有功能的确认，也不代表官方推荐这些工作流。

## 如何使用这本实践分册

从自己的任务选择一例，替换合成输入前先做脱敏和权限检查。初学者先只在聊天中产生草稿，不接账号、不装插件、不执行外来代码；完成验收后再由有权限人员进入真实流程。每个案例的预计时间是教学设计预算，不是实测效率承诺。

共同闸门：输入合法且最小化 → 任务范围明确 → 草稿带来源和缺口 → 按rubric验收 → 人工批准涉及外部状态的操作。涉及真实考试、签发用印、付费墙、法律效力或敏感资料时，不以“练习”为理由绕过限制。

## L01 把陌生概念学到能够解释：提问式学习教练

**适用岗位/用户：** 新入职员工、成人自学者。**难度：** 入门至进阶。**预计练习预算：** 25分钟。

**输入（全部合成、非隐私）：** 合成材料：某练习公司以“任务到达→分派→完成→复核”处理工单；排队时间12分钟，处理时间8分钟。学习者自述：不理解等待时间与处理时间区别。

**目标：** 在不先给标准答案的情况下，让学习者自行解释两个指标并用新情境检验理解。

### 分步操作

1. 先声明非考试任务，收集已有理解、每天可用20分钟及学习目标。
2. 让agent只问一个诊断问题：客户实际等待多久，为什么？学习者先写推理。
3. 根据回答给最小提示，再让学习者画四阶段文字流程。
4. 使用变式：等待减为6分钟、处理不变；学习者独立计算并解释。
5. 最后把误区、纠正依据和下一次回忆问题记录在个人反思卡。

### 可复制提示模板

```text
你是提问式学习教练。仅用下面合成材料教我【概念】。先问一个问题并等待我的回答，不要一次输出答案。根据我的推理提供一级提示；仍不理解才给更具体提示。完成后要求我用自己的话解释并做一题不同情境的迁移练习。禁止替我完成正在进行的考试或受限考核。材料：【粘贴】。
```

### 预期输出

- 概念边界卡：等待时间不等于处理时间。
- 学习者自己的解释、一次迁移题作答和误区日志；答案单独折叠保存。

### 验收 Rubric

- 解释准确0–2分；能指出边界0–2分；迁移推理0–2分；反思具体0–2分。≥6/8且解释准确为2才完成。
- 学习者先作答、agent后反馈为硬门槛；不得以聊天轮数代替学习成效。

### 常见失败与修复

- agent直接泄露答案：重置为只提供一个提示，换一组数字重新测。
- 概念解释与材料冲突：逐句回到材料，不用流畅程度评分。

**授权边界：** 只保存用户选择保留的学习记录；不上传学生身份、成绩、诊断信息；涉及未成年人遵循监护及机构规则。

**证据等级：** D：官方文档依据＋原创教学设计，未实测。相关原则依据：[S1](https://www.unesco.org/en/articles/guidance-generative-ai-education-and-research)。这些来源支持原则或工具机制，不证明该案例已实施或有效。

## L02 用错误日志安排七天复习，而不是堆积题库

**适用岗位/用户：** 职业转岗者、培训学员。**难度：** 入门至进阶。**预计练习预算：** 30分钟。

**输入（全部合成、非隐私）：** 合成错题记录：百分比变化把分母写错2次，日期排序错1次，平均数与中位数混淆3次；每天15分钟，周末30分钟。

**目标：** 形成可调整的复习安排，并用独立回忆证据判断是否掌握。

### 分步操作

1. 把每条错误转换为知识点、错误原因和信心等级，不把“粗心”当最终原因。
2. agent给三个低风险练习，学习者闭卷完成；每题记录理由。
3. 按用户时间预算排七天任务，交替安排旧题与新情境题。
4. 第3天和第7天让学习者独立解释；根据新错误调整后续任务。
5. 输出复盘：哪些错误减少、哪些仍未解决，不宣称固定计划必然提高分数。

### 可复制提示模板

```text
根据我的合成错误日志【日志】与时间预算【预算】，设计7天复习表。每次包含回忆问题、短练习、自我解释和反思；先给题目，不给答案。把“已掌握”的条件写成可观察表现，允许根据第3天表现调整。不要预测考试分数，不生成任何真实在考题答案。
```

### 预期输出

- 七天任务表：日期、时间预算、回忆点、练习、完成证据、调整条件。
- 错误类型对照表及第3天/第7天自评记录。

### 验收 Rubric

- 每天总时长不得超预算；每个错误点至少有一次迁移验证。
- 掌握判断必须有学习者独立回答；完成率与准确率分开统计。
- 未解决错误如实列出，不能把未练习标为掌握。

### 常见失败与修复

- 任务超量：删除低优先级练习，不压缩必要休息。
- 同类题机械答对：换表示方法并追问理由；答案记忆不算迁移成功。

**授权边界：** 学习建议不是保证成绩的承诺；不读取真实考试平台、代交作业或绕过教学限制。

**证据等级：** D：官方文档依据＋原创教学设计，未实测。相关原则依据：[S1](https://www.unesco.org/en/articles/guidance-generative-ai-education-and-research)。这些来源支持原则或工具机制，不证明该案例已实施或有效。

## L03 为培训师制作有检验点的微课程

**适用岗位/用户：** 企业培训师、公益讲师。**难度：** 入门至进阶。**预计练习预算：** 40分钟。

**输入（全部合成、非隐私）：** 合成培训主题：如何给文件命名。规则：项目-日期-主题-版本；示例“星河-20261101-培训-v01”。对象为初次接触版本管理的12位成人。

**目标：** 产出一份20分钟的教学脚本，包含练习、反馈和无障碍替代材料。

### 分步操作

1. 先写出一个可观察学习目标：看见三个文件名能识别项目、日期和版本。
2. 按解释3分钟、示范4分钟、练习8分钟、复盘5分钟拆分。
3. agent生成正确示例、容易混淆的反例及解释；培训师逐项核对。
4. 制作纯文本讲义与口头描述，避免只有颜色区分版本。
5. 用三份合成文件名试讲并观察学习者能否独立改名；保存修改记录。

### 可复制提示模板

```text
为【成人新手】设计20分钟【文件命名】微课程。只使用我给的规则【规则】。输出学习目标、分钟脚本、2个正例与2个反例、独立练习和评分标准、纯文本版讲义。对可能不同的组织规则标注“本课练习约定”，不得写成行业强制标准。
```

### 预期输出

- 培训脚本与讲义草稿。
- 练习题、单独答案页、培训师观察表。

### 验收 Rubric

- 时长合计20分钟；目标、练习、评分项目一一对应。
- 4个例子的判定都能由练习规则推出；不得凭空引入强制规范。
- 不看幻灯片也能完成练习；至少提供一种非视觉线索。

### 常见失败与修复

- 课程变成概念堆砌：删到一个目标，增加独立操作。
- 输出只含彩色提示：加入版本号与文字说明。

**授权边界：** 培训师批准后才向学员分发；不收集残障诊断以提供替代材料。

**证据等级：** D：官方文档依据＋原创教学设计，未实测。相关原则依据：[S1](https://www.unesco.org/en/articles/guidance-generative-ai-education-and-research)、[S5](https://www.w3.org/WAI/tips/writing/)。这些来源支持原则或工具机制，不证明该案例已实施或有效。

## L04 从事项卡起草公文待审稿：请示与报告不混写

**适用岗位/用户：** 机关文秘学习者、事业单位综合岗。**难度：** 入门至进阶。**预计练习预算：** 40分钟。

**输入（全部合成、非隐私）：** 纯虚构事项卡：青禾服务中心拟新增一个阅读角；申请事项为是否同意使用现有空置房；预算未定、主管单位未定、政策依据未提供。所有机构均为教学化名。

**目标：** 输出正确暴露信息缺口的待审结构，不把拟申请写成已批准。

### 分步操作

1. 确认用途是练习，先识别行文目的、关系和是否请求批准；未知关系不得猜测。
2. 将提供信息分成已知事实、拟议安排、待核实依据与审批缺口。
3. agent提出文种判断理由及待确认项，再给带明显“教学待审稿”标识的结构。
4. 逐条映射正文事实到事项卡；预算、政策、文号、签发人全部保留待填。
5. 由真实业务场景的文秘人员检查适用格式、行文关系与审批程序；本练习不发文。

### 可复制提示模板

```text
你协助做公文教学练习，不代表机关。根据【事项卡】先判断写作目的与信息缺口，再拟【待审稿】。任何无来源的政策、金额、主管单位、文号、签发人、成文日期不得补造。把请求事项与汇报事实分开；无法确定文种时先列判断条件。输出事实来源表、待核清单和审批节点，不加签章、不发文。
```

### 预期输出

- 教学待审稿结构：事由、事实基础、拟请示事项、附件占位。
- 事实—输入编号映射表及文种/审批待确认清单。

### 验收 Rubric

- 硬门槛：虚构政策、文号、签章、审批结论任一出现即失败。
- 事实可追溯率100%；未知项标注率100%；拟议与已批准表述完全分离。
- 格式须依据本单位经确认的模板复核；不能凭排版相似宣称规范合格。

### 常见失败与修复

- agent编造“根据某文件”：删去该句并登记依据缺口，待用户提供真实依据。
- 把申请写成决定：恢复“拟/申请”语气，并由业务负责人确认事项。

**授权边界：** 不得输入涉密公文；模板草拟不等于签发授权。正式收发、编号、用印、签发、归档必须由有权限人员依程序办理。

**证据等级：** D：官方文档依据＋原创教学设计，未实测。相关原则依据：[S2](https://www.mem.gov.cn/xw/ztzl/2018/cyzd/lxyz/201207/t20120708_228323.shtml)。这些来源支持原则或工具机制，不证明该案例已实施或有效。

## L05 核对公文稿的数字、附件和审批缺口

**适用岗位/用户：** 文秘复核岗、综合办公室助理。**难度：** 入门至进阶。**预计练习预算：** 30分钟。

**输入（全部合成、非隐私）：** 合成待审稿称开展3场培训，附件列2场；正文写参与60人，附件合计20+25=45人；地点有“东楼/西楼”冲突；无签发记录。

**目标：** 把差错转成可核查问题单，而不是让agent自行选择正确版本。

### 分步操作

1. 锁定输入版本与各段编号，保留原稿不覆盖。
2. 抽取日期、人数、地点、附件编号和引用依据，生成事实台账。
3. 对可计算项重新计算，对不一致项并列呈现，不猜哪个正确。
4. 按事实、结构、格式、审批四类列检查结果；格式项依已提供模板核对。
5. 业务负责人填写核实结果，文秘重新核对后保留改动说明与待签状态。

### 可复制提示模板

```text
检查这份虚构公文待审稿【正文】及【附件】。不直接改写事实。输出问题ID、原文位置、两处冲突、需谁确认、建议修订方式。数字允许做明确计算但不得补全缺失数据。审批记录缺失标“未提供”，不写成已通过。不得生成印章或签字。
```

### 预期输出

- 问题单：场次3/2冲突、人数60/45冲突、地点冲突、签发记录未提供。
- 保留差异的修订建议稿和复核状态表。

### 验收 Rubric

- 4类已埋问题全部检出；计算45正确。
- 不把冲突自动合并；不把“未提供签发记录”推断为违法或已签发。
- 每项修订保留原因及确认人占位；原稿仍可追溯。

### 常见失败与修复

- 自动采用正文数字：退回冲突状态，要求附件负责人核实。
- 校对过度改动政策表述：撤回无授权改写，只标注需主管复核。

**授权边界：** 仅做辅助检查；不能替代合法性审查、保密审查或正式签发；真实文件限在单位批准环境处理。

**证据等级：** D：官方文档依据＋原创教学设计，未实测。相关原则依据：[S2](https://www.mem.gov.cn/xw/ztzl/2018/cyzd/lxyz/201207/t20120708_228323.shtml)。这些来源支持原则或工具机制，不证明该案例已实施或有效。

## L06 把冗长说明改成能执行的操作指引

## L07 从事实卡生成文章大纲与引用账本

**输入（全部合成、非隐私）：** 合成长说明含标题、三步提交流程、两个同名“点击这里”链接、一张只写“流程图”的图片描述。

**目标：** 在不承诺已通过WCAG审计的前提下准备语义清晰的内容结构。

### 分步操作

1. 列出页面目标、读者主要任务和章节树，避免靠字号表现层级。
2. agent建议唯一页面标题与有逻辑的标题层级。
3. 将链接文本改为目标描述，保留实际目标待核；图片按用途提供替代文本建议。
4. 输出线性阅读顺序与纯文本版本，检查是否有“看右边”一类位置依赖。
5. 由有权限编辑者实现后，用键盘和屏幕阅读器实测导航；本研究不声称已完成。

### 可复制提示模板

```text
请审查【页面文案】，给内容层面的无障碍改写建议。输出标题树、阅读顺序、意义明确的链接文字、图片说明与缺失信息。不要只改变字体大小；不要自动发布或声称WCAG合规。把需要开发者和真实辅助技术验证的项单列。
```

### 预期输出

- 页面内容结构稿与改写对照。
- 待验证清单：语义标题、键盘顺序、链接目标、屏幕阅读器结果。

### 验收 Rubric

- 标题逻辑清晰；两个不同目的链接有不同且可理解的名称。
- 正文不依赖颜色或左右位置；图片不能只描述为“图片”。
- 文案复核通过与技术无障碍通过分别记录，不能互相替代。

### 常见失败与修复

- 用加粗冒充标题：要求实现时使用真实标题语义。
- 链接目标未知：保留待核，不创造网址。

**授权边界：** 只准备待审稿；代码实施、上线和合规宣称须由授权责任人验证。

**证据等级：** D：官方文档依据＋原创教学设计，未实测。相关原则依据：[S5](https://www.w3.org/WAI/tips/writing/)、[S7](https://www.w3.org/WAI/tutorials/page-structure/)。这些来源支持原则或工具机制，不证明该案例已实施或有效。

## L14 多语言办公说明：术语一致、数字不变、人工复核

**适用岗位/用户：** 跨语言团队协调者、国际志愿项目编辑。**难度：** 入门至进阶。**预计练习预算：** 35分钟。

**输入（全部合成、非隐私）：** 合成中文说明：“试用培训在2026年11月5日14:00 UTC开始，时长45分钟。请在11月3日前确认。”术语表：试用培训=pilot training；负责人只给角色名。目标语言英语。

**目标：** 生成保留事实与不确定性的双语待审稿，而不是未经复核的正式承诺。

### 分步操作

1. 确认目标受众、语言区域、语气和术语表；确认日期截止是否包含当日。
2. 先抽取不可变字段：日期、时间、时区、时长、角色名。
3. agent逐段翻译，术语一致；模糊截止语义留待确认，不自行消除。
4. 对照核查数字、否定词、义务语气与姓名；回译只作提示，不当作正确性证明。
5. 双语审校者批准后发布；若网页展示，标记页面和局部文本语言，另测读屏效果。

### 可复制提示模板

```text
将【中文合成说明】译为【目标语言/地区】的待审稿。严格遵循【术语表】，不更改日期、UTC时区、时长和角色。输出双语对照、不可变字段核对表、歧义清单。不能确认截止日含义时保留疑问，不增强承诺。若用于网页，提供语言标记建议但不声称已实现或验证。
```

### 预期输出

- 双语对照稿、术语表与字段校对表。
- 歧义清单：“11月3日前”的具体截止时点待组织者确认。

### 验收 Rubric

- 2026-11-05、14:00 UTC、45分钟全部保留；无隐式时区换算。
- pilot training术语一致；没有把“请确认”升级成惩罚性要求。
- 人工语言复核与网页语言标记验证分开记录；不能只用回译判定准确。

### 常见失败与修复

- 自动转换时区造成日期错误：保留UTC，只有明确要求才换算并列出原时间。
- 同一术语多个译法：用术语表统一，再请双语审校者确认自然度。

**授权边界：** 翻译法律、医疗或具有法律效力文书需合格专业人员审核；未经授权不代发、不代签、不声称官方译本。

**证据等级：** D：官方文档依据＋原创教学设计，未实测。相关原则依据：[S8](https://www.w3.org/International/questions/qa-html-language-declarations)。这些来源支持原则或工具机制，不证明该案例已实施或有效。

## 可用于学习平台的功能要求（建议，非已实现能力）

1. 每例提供“查看合成输入”“复制模板”“提交自己的结果”“对照rubric”四个入口；参考答案与学习者初次作答分离。
2. 页面卡片同时显示岗位、任务、难度、时间预算、权限风险、查证日期、证据等级；不得把“有官方来源”呈现为“已实测”。
3. 公文案例设置醒目的待审标签，禁用自动编号、用印和签发暗示；保留事实来源、缺失项与审核清单。
4. 研究案例分别展示来源可访问性、元数据核验和全文核验，不用单一可信度百分比掩盖证据缺口。
5. 练习提交可只保存在用户本地；示例展示不要求真实姓名、单位、健康或成绩资料。
6. 可访问性提供纯文本材料、键盘可达控件、合理标题及语言标记；必须有实际辅助技术测试才能报告技术验收。
7. 每次内容更新保留旧版、变更原因及来源查证记录；超期或来源失效时标“需复核”，不自动宣称过时或仍然有效。
